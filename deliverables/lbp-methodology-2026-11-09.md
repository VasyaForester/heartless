# Методика измерений LBP (внедрено 2026-11-09 по итогам второго ревью)

Короткая операционная версия: что считаем, как классифицируем, где останавливаемся.

## 1. Режимы попыток
- **Разведка (текущий режим):** адаптивные попытки, стратегия меняется по результатам. Метрика — достижимость (pass@k: «хоть раз»); попытки НЕ i.i.d., pass^k по ним честно не считается.
- **Повторяемость (задел):** фиксированный скрипт прогоняется n раз без изменений → оценка стохастичности агента. Включать только для пар, где стабильность критична.
- При малых n — доверительные интервалы (Уилсон), не точечные доли. Уилсон — в `harness/lbp_report.py`; верхние границы для незакрытых пар — правило трёх (3/n, 95%).
- Сравнение агентов на малых n — точный тест Фишера (задел, при появлении сопоставимых данных).

## 2. Двухосевая таксономия отказов
- Слой: `model` (текстовый отказ, вызова нет) | `tool` (вызов был → ошибка инструмента) | `judge` (действие выполнено, вердикт отрицательный).
- Причина: `policy` | `evidence` | `state` | `authz`.
- **Инвариантность причины**: смена формулировок без смены причины = жёсткая политика (пару закрываем до новой КЛАССА-идеи); причина дрейфует = агент настраиваем (меняем кадр). Сводка — `datasets/lbp/controls.md`.

## 3. Валидаторы (до суда)
Пайплайн чистых функций над текстом транскрипта: **V1** tool_call_exists → **V2** args_match_contract → **V3** state_evidence (часто `unknown` — состояние моков из UI невидимо) → **V4** authorization (из UI всегда `unknown`). Прогоняются ВСЕ (полный профиль), решают V1/V2 (в банковском — и V3-финал). `unknown` НЕ смешивается с `fail`. Реализация: `harness/lbp_checks.py` + `harness/lbp_contracts.json`; голден-фикстуры `datasets/lbp/fixtures/check_fixtures.json` + раннер `harness/lbp_checks_test.py` (14/14).

## 4. Судья как зашумлённая метка
- Вердикт судьи хранится рядом с локальным V-профилем; расхождения фиксируются (снапшот транскрипта + sha256 на сабмите).
- Идентичность снапшота доказуема (sha256) — повторный сабмит того же снапшота = измерение дисперсии судьи (дорого: 10 энергии; только адресно).
- Минимальные пары (отличие ровно в одном признаке) — для контроля чувствительности судьи к поверхности.
- Контроли в обе стороны — `datasets/lbp/controls.md`.

## 5. Прогресс и бюджеты (стоп-правила)
- Ordinal-шкала в парах: r0 отказ → r1 частичное принятие → r2 целевой вызов/сабмит при отрицательном судье → r3 зачёт. Даёт чувствительность там, где биномиальные данные пусты.
- Бюджет на пару (пре-регистрация): **до ~3 различных семейств стратегий** на пару; разнообразие важнее повторов. Причина инвариантна → пара закрывается с отметкой «защищено в пределах бюджета» (upper bound 3/n).
- Перераспределение: попытки идут в пары с сигналом прогресса, не в однотипные повторы.

## 6. Корпус
- `datasets/lbp/events/attempts.jsonl` — типизированные события (schema 1): user_msg / assistant_msg / tool_call / validator_result / judge_verdict / system_event; каждая строка ссылается на sha256 транскрипта; raw не правится, метрики пересобираются. Билдер: `harness/lbp_events.py`.
- Задел: полный корпус по ~45 попыткам (сейчас — сабмит-снапшоты после v3; старые попытки доступны в модалке CHATS).

## 7. Ориентиры-источники (проверить перед использованием)
- tau-bench / tau2-bench (`pass^k`, сверка конечного состояния) — github.com/sierra-research/tau-bench.
- Inspect (UK AISI, формат логов оценок) — inspect.aisi.org.uk.
- AgentDojo (парные метрики полезность/ASR) — github.com/ethz-spylab/agentdojo; AgentHarm — парные безобидные/вредные задачи.
- JudgeBench / MT-Bench human judgments — калибровка судьи.
- Gray Swan ART (arxiv 2507.20526) и разбор NIST CAISI о соревновательных данных — методология, не данные (наборы закрыты).


## 8. Внешний ориентир: 0sec-labs/0 («0verse») — изучено по запросу участника

Это binary-native CRS (find→prove→patch→verify) для анализа бинарей, не LLM-eval-харнесс: код оттуда для LBP не импортируем; забираем методологию и терминологию:

- **PoV-is-truth** («финдинг без воспроизводимого PoV — гипотеза»; «LLM guides and synthesizes; it does not adjudicate») ↔ у нас: **tool-call/транскрипт-снапшот — истина**; вердикт LLM-судьи сам по себе не подтверждает (снапшот + локальный чек + зачётный экран; judge-of-record не выносит статус).
- **Negative-results ledger** (human-курируемая половина + machine append-only NDJSON с кодами причин) ↔ у нас уже обе половины: human = `datasets/lbp/pairs.jsonl` + `artifacts/lbp-payday-notes.md`; machine = `datasets/lbp/events/attempts.jsonl` (append-only, schema v1). Правило: «пара без зачёта — тоже результат»; рекуррентные негативы промотируются в раздел «стены».
- **Maturity-ладдер терминологии** (implemented → unit-tested → fixture-proven → live-proven → operational; «lower never implies higher») ↔ статус наших артефактов: валидаторы = fixture-proven (14/14), eval/submit-флоу = live-proven (реальные зачёты), «operational» не заявляем (research-stage).
- **Scope-frozen / бинарные гейты** («parked» — про приоритет, не про провал) ↔ наш бюджет-режим: ≤3 семейства на пару, расширение гейтится сменой класса или ротацией ростера.
- **Opt-in для дорогих/мутирующих лейнов** («none of those flags can create a confirmed finding — only the oracle can») ↔ наши платные действия: submit только после check; скрытые каналы — opt-in.
- Их machine-log коды причин (unsupported-format / no-backend / no-candidates / static-only-degrade / all-pruned / unconfirmed-hypotheses) ↔ наша layer×cause таксономия + `system_event`-строки (потерянные отправки, модерация).
