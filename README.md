# gray-swan-harness

Инфраструктура для **непрерывного** прохождения AI-red-team испытаний на аренах Gray Swan
(доски `Lucky Break: Payday` и `Proving Ground`): планирование проб, отправка через
авторизованный браузер, привязка судейских вердиктов к конкретной попытке, накопление
статистики и адаптивный выбор следующей формулировки.

Это не библиотека и не приложение. Это рабочий стенд под конкретную задачу: **как можно
больше подтверждённых решений при ограниченной энергии**, с воспроизводимостью каждого шага.

## Что внутри в одном экране

```
tools/lane_auto.sh ──▶ harness/supervisor.py ──▶ harness/driver.py
   (запуск лейна)         (жизненный цикл,          (цикл: выбор пары →
                            сторож зависаний)         выбор руки → отправка →
                                                      доказательства → награда)
                                                        │
        ┌───────────────────────────────────────────────┼──────────────────────────────┐
        ▼                                               ▼                              ▼
harness/arena.py                             harness/store.py               harness/strategy.py
(шов площадки: транспорт,                    (SQLite: попытки, состояния,   (политики выбора руки,
 доказательства, раскладка)                   lease, best/latest, награды)   память экспериментов)
        │                                               │                              │
        ▼                                               ▼                              ▼
  harness/lbp.py + hackathon.py               harness/judge_ledger.py        harness/strategy_bench.py
  (CLI арены через CDP)                       (вердикт ↔ operation id)       (офлайн-полигон политик)
```

Ключевые модули:

| Модуль | Ответственность |
|---|---|
| `harness/supervisor.py` | запускает драйвер, следит за ростом лога (зависание ≠ долгая попытка), пере-базирует манифест |
| `harness/driver.py` | цикл: пара → рука → отправка → доказательства → награда → финализация; планировщик покрытия пар |
| `harness/arena.py` | интерфейс площадки (`ArenaAdapter`) + реализация Gray Swan; новая арена = один адаптер |
| `harness/store.py` | схема БД, состояния попытки, lease с владельцем, `best_*`/`latest_*`, награда |
| `harness/judge_ledger.py` | привязка судейского артефакта к `operation id` (а не к файлу пары) |
| `harness/strategy.py` | политики выбора (random/ucb/ucb_improved/thompson/contextual_ts), память экспериментов, локальная награда |
| `harness/strategy_bench.py` | офлайн-полигон: train/test, Wilson-CI, свип бюджетов, аблация маппинга награды |
| `harness/ab_report.py` | живой рандомизированный A/B (генерация кадров против повтора дельты) |
| `harness/reward_audit.py` | аудит канала награды: наши собственные сбои vs отказы модели, монотонность прокси к судье |
| `harness/frames.py`, `candidate.py` | генерация новых формулировок (композиция: носитель × доставка × требование) |
| `harness/config_check.py` | сторож дрейфа «код ↔ RULES ↔ CLAUDE.md ↔ профили доски ↔ README» |

## Как запустить

```bash
# офлайн-набор тестов (браузер и энергия не нужны)
python3 harness/run_offline_tests.py

# проверка согласованности документации, правил и профилей досок
python3 harness/config_check.py

# один лейн (нужен авторизованный Chrome с CDP на 127.0.0.1:9223)
python3 harness/supervisor.py --lane main --target "<id цели>" --max-hours 0

# полигон политик и живой A/B
python3 harness/strategy_bench.py --budget 300 --seeds 21 --sweep 100,300,1000
python3 harness/ab_report.py
```

Доска выбирается переменной `HERMES_BOARD` (или профилем в `boards/*.json`); профиль доски —
данные, логики в нём нет. Документы, обязательные к прочтению перед изменением цикла:
`RULES.md` (правила и защищённые файлы), `CLAUDE.md` (режим работы), `HARNESS-TREE.md`
(карта дерева).

## Принципы, которые здесь дороже скорости

1. **Вердикт привязывается к попытке, а не к паре.** Судейский артефакт читается по
   `operation id`; пер-парный файл перезаписывается каждой отправкой и отдаёт вердикт
   предыдущей пробы (измеренный дефект: 104 из 114 попыток).
2. **«Вердикта ещё нет» — не ошибка**, а нетерминальное состояние: поздний вердикт
   подбирается до следующей пробы, без повторной отправки.
3. **Планирование и выбор руки — разные решения.** Какую пару пробовать — покрытие
   (давность/кулдаун), какую формулировку внутри пары — бандит по наградам. Локальная
   награда сравнивает руки только ВНУТРИ пары.
4. **Наши собственные сбои — не данные.** Проба, которую не донёс наш же шаг отправки,
   не получает награды и считается дефектом стенда.
5. **«Не решено» — легальный ответ.** У любого сравнения есть порог по числу наблюдений;
   вердикт из нескольких проб не выводится.
6. **Утверждение без замера — не утверждение.** Спорные решения (выбор политики, цена
   генерации) выносятся в офлайн-полигон и рандомизированный живой A/B, а не в описание.

## Что здесь НЕ делается

- Не обходится авторизация и не используются чужие учётные данные: работает только
  авторизованная браузерная сессия оператора.
- Не отправляются повторные запросы вслепую: неопределённый результат отправки не
  переигрывается автоматически.
- Не утверждается, что стенд «решает» арену: считаются подтверждённые решения, а не попытки.

## Проверено

`python3 harness/run_offline_tests.py` — офлайн-набор без браузера и без энергии;
`harness/config_check.py` — согласованность документации с кодом и профилями досок.
Обе команды входят в Definition of Done любого изменения цикла.
